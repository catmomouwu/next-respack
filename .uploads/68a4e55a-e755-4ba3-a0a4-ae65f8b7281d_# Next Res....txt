# Next Respack — 完整项目开发、安装与部署任务书

你是一支完整的软件工程团队，由系统架构师、PHP 后端工程师、前端工程师、数据库工程师、安全工程师、测试工程师和 DevOps 工程师组成。

请从零开始设计、开发并交付 **Next Respack**。

本项目是一个专门面向 Minecraft Java Edition 服务器管理员的资源包上传、管理、校验、托管和下载平台，不是通用网盘。

必须实际创建工程文件、实现业务逻辑、编写数据库迁移、实现前端、执行测试并提供完整部署发行包。

不得只输出架构方案、静态页面或伪代码。

# 一、项目技术架构

## 1.1 技术栈

- PHP 8.3+
- Laravel 13
- MySQL 5.7+（首选）
- MariaDB（通过兼容性测试后支持）
- SQLite（可选轻量部署模式）
- Blade
- Tailwind CSS
- Alpine.js
- Vite
- Laravel Filesystem
- PHPUnit 或 Pest

要求：

1. 依赖版本必须兼容 PHP 8.3。
2. 数据库最低兼容 MySQL 5.7。
3. 不得使用仅在 MySQL 8.0 中存在的 SQL 特性作为核心功能前提。
4. 不得依赖 MySQL 8.0 专属函数、索引特性或约束行为。
5. 所有数据库迁移必须实际在 MySQL 5.7 和 MySQL 8.0 上测试。
6. 使用 `composer.lock` 固定依赖。
7. 生产发行包预先包含 Composer 依赖和前端构建产物。

## 1.2 目标部署环境

### A. 虚拟主机

目标：

- PHP 8.3
- MySQL 5.7 或 8.0
- Apache 或 Nginx
- HTTPS
- FTP/SFTP 上传
- 不保证 SSH。
- 不保证 Composer CLI。
- 不保证 Node.js。
- 不保证 Cron。
- 不保证 Root 权限。
- 不保证可以修改服务器全局配置。

必须支持：

- 无需用户运行 Composer。
- 无需用户运行 npm。

# 二、首次访问安装向导

必须提供完整的浏览器安装向导。

首次访问时自动检测安装状态：

- 未安装：跳转 `/install`。
- 已安装：正常进入网站。
- 正在安装：恢复受保护的安装流程。
- 安装完成：安装入口永久锁定。

## 2.1 安装步骤

### Step 0：欢迎页面

显示：

- Next Respack Logo。
- 产品名称。
- 产品版本。
- 简体中文 / English。
- 安装说明。
- 开始安装按钮。

### Step 1：环境检测

检测：

- PHP 版本是否不低于 8.3。
- MySQL PDO 驱动。
- 必需 PHP 扩展。
- ZIP 扩展。
- 文件上传限制。
- PHP 内存限制。
- 执行时间。
- `storage/` 写入权限。
- `bootstrap/cache/` 写入权限。
- 磁盘可用空间。
- HTTPS。
- 前端资源是否存在。

显示通过、警告、失败状态及修复方法。

缺少必需环境时禁止继续。

### Step 2：数据库配置

支持选择：

- MySQL。
- MariaDB（通过兼容性测试后开放）。
- SQLite（可选）。

MySQL 配置：

- Host
- Port
- Database
- Username
- Password
- Charset
- Collation

默认：

```text
Port: 3306
Charset: utf8mb4
Collation: utf8mb4_unicode_ci
```

必须提供数据库连接测试。

检测：

- 数据库版本。
- 数据库是否可连接。
- 数据库是否存在。
- 数据库账号权限。
- 是否存在同名应用数据表。

虚拟主机通常不允许普通数据库账号创建数据库，因此必须允许直接使用服务商预先创建的数据库。

安装器只在选定数据库中创建应用表，不得删除或覆盖无关数据表。

**最低兼容版本必须是 MySQL 5.7。**

### Step 3：存储后端选择

安装器必须提供三种正式存储选项：

1. 本地存储。
2. S3 兼容对象存储。
3. WebDAV 存储。

默认选择本地存储。

#### A. 本地存储

默认目录：

```text
storage/app/private/resource-packs/
```

配置：

- 存储路径。
- 目录写入测试。
- 可用空间检测。
- 路径安全检测。

不得直接公开资源包文件。

#### B. S3 兼容存储

支持：

- Amazon S3
- Cloudflare R2
- 其他 S3-compatible 服务

配置：

- Endpoint
- Region
- Bucket
- Access Key
- Secret Key
- Path Style
- 自定义域名（可选）

必须测试：

- 连接。
- 上传。
- 读取。
- 删除。
- 对象是否存在。

默认禁止公开 Bucket。

#### C. WebDAV 存储

WebDAV 必须作为正式的一级存储后端，直接加入首次安装向导。

配置字段：

- WebDAV Server URL
- WebDAV Username
- WebDAV Password
- WebDAV Base Path
- Connection Timeout
- Request Timeout
- TLS Certificate Verification
- 自定义根目录（可选）

例如：

```text
WebDAV URL:
https://dav.example.com/remote.php/dav/files/username/

Username:
username

Password:
********

Base Path:
/NextRespack/
```

安装时必须执行连接测试：

1. 测试 WebDAV 服务可连接。
2. 测试身份认证。
3. 检查目标目录。
4. 必要时创建目标目录。
5. 测试上传临时文件。
6. 测试读取临时文件。
7. 测试删除临时文件。
8. 检查服务器是否支持必要的 HTTP 操作。

必须正确处理：

- HTTP Basic Authentication。
- HTTPS。
- PUT。
- GET。
- DELETE。
- MKCOL。
- MOVE（如果服务端支持）。
- PROPFIND（如果服务端支持）。

如果某个 WebDAV 服务不支持原子 MOVE，必须提供安全的替代上传策略。

WebDAV 文件路径不得由用户输入直接拼接，必须进行路径规范化和目录边界检查。

WebDAV 密码必须加密保存，不能明文暴露在普通管理界面、日志或 API 返回值中。

修改存储后端时不能自动删除原存储数据。

必须提供存储迁移功能，支持：

- 本地迁移到 WebDAV。
- WebDAV 迁移到本地。
- 本地迁移到 S3。
- S3 迁移到 WebDAV。
- WebDAV 迁移到 S3。

迁移时逐个校验文件大小和 SHA-1，全部验证成功后才更新数据库中的存储位置。

不得在未完成迁移前删除源文件。

#### 统一存储接口

采用统一 Storage Adapter：

```text
StorageInterface
├── LocalStorageAdapter
├── S3StorageAdapter
└── WebDAVStorageAdapter
```

上传、删除、读取、检查、迁移和下载业务不得直接绑定具体存储服务。

对于 WebDAV 和 S3，不得假设可以使用 Nginx `X-Accel-Redirect` 直接读取远程对象。

远程文件应通过受控流式下载或经过验证的短期签名访问方式提供。

# 四、游客上传功能

必须允许未注册游客直接上传 Minecraft 资源包。

游客上传是独立的上传身份体系，不要求游客创建账户。

## 4.1 游客上传限制

游客上传规则：

- 单个文件最大 200 MB。
- 每个游客上传文件最多保留 7 天。
- 超过 7 天自动删除。
- 不提供永久保存保证。
- 上传后立即生成匿名 HTTPS 下载链接。
- 游客不需要登录即可下载。
- 游客上传后可以查看 SHA-1。
- 游客可以生成 Minecraft 服务端配置。

**页面必须明确显示：游客上传的文件将在 7 天后自动删除；注册账户上传的文件可以永久保存，直至用户主动删除或违反平台管理规则。**

不得让用户误以为游客文件永久保存。

## 4.2 游客上传管理

游客没有用户仪表盘，因此必须设计安全的上传管理方式。

上传完成后生成：

- 下载 Token。
- 管理 Token。
- 上传记录 ID。

管理 Token 必须是独立的高熵随机值，与下载 Token 分离。

游客可以通过安全管理链接查看：

- 文件名。
- 文件大小。
- SHA-1。
- 上传时间。
- 预计过期时间。
- 下载链接。
- 服务端配置。

游客管理 Token 不得暴露在下载 URL 中。

允许游客通过管理链接：

- 修改显示名称。
- 查看文件信息。
- 提前删除文件。
- 查看剩余保存时间。

游客管理链接必须具备足够随机性，不得使用连续 ID。

管理 Token 只保存摘要。

## 4.3 游客过期清理

游客文件必须保存：

- `upload_type`。
- `guest_token_hash`。
- `expires_at`。
- `created_at`。
- `deleted_at`。

注册用户文件与游客文件必须能够明确区分。

游客上传默认：

```text
upload_type = guest
retention_days = 7
max_file_size = 200 MB
```

注册用户上传：

```text
upload_type = registered
expires_at = NULL
```

游客文件过期后：

1. 下载链接立即失效。
2. 管理链接失效。
3. 数据库记录进入待删除状态。
4. 删除本地或远程存储中的文件。
5. 清理下载统计关联数据。
6. 记录清理日志。

必须考虑 WebDAV、S3 和本地存储删除失败的情况。

删除失败时进入重试队列或待清理列表，不得假装已经删除。

## 4.4 无 Cron 环境

虚拟主机可能没有 Cron。

因此：

- VPS 使用 Laravel Scheduler。
- 虚拟主机优先提供 Cron 配置。
- 无 Cron 时使用限频的请求触发清理。
- 也提供管理员手动清理按钮。
- 每次清理必须使用锁防止并发执行。
- 每次请求不能重复扫描全表。
- 清理必须分批执行，避免 PHP 超时。

过期时间必须以数据库记录的 `expires_at` 为准，而不是只依赖定时任务是否执行。

即使清理任务尚未运行，过期文件也必须禁止下载。

## 4.5 防滥用

游客上传必须提供：

- IP 限流。
- 上传频率限制。
- 单 IP 并发限制。
- 文件大小限制。
- ZIP 安全校验。
- 可配置验证码。
- 管理员关闭游客上传的开关。
- 游客文件总量限制。
- 全站游客存储配额。

如果记录 IP，必须考虑隐私保护和数据保留期限。

# 六、Minecraft 资源包校验

只允许 Minecraft Java Edition 资源包 ZIP。

必须检查：

- 文件扩展名。
- MIME。
- ZIP 文件签名。
- ZIP 完整性。
- CRC。
- 文件数量。
- 解压后总大小。
- 压缩比。
- ZIP Bomb。
- 路径穿越。
- 符号链接。
- 文件名安全。

检查 ZIP 根目录：

```text
pack.mcmeta
```

可选：

```text
pack.png
```

解析：

- `pack`。
- `pack_format`。
- `supported_formats`。
- `min_format`。
- `max_format`。
- 描述信息。

必须保留原始 `pack.mcmeta`。

状态：

- ZIP_INVALID
- PACK_INVALID
- METADATA_INVALID
- FORMAT_UNKNOWN
- VALID
- VALID_WITH_WARNING

不得把任意 ZIP 文件错误识别为合法 Minecraft 资源包。

# 七、Minecraft Resource Pack Format 数据模块

数据源：

https://minecraft.wiki/w/Pack_format

必须完整采集 Minecraft Java Edition Resource Pack Format 历史映射。

不允许混入 Data Pack Format 或 Bedrock Edition 格式。

## 7.1 数据范围

包括：

- 正式版。
- Snapshot。
- Pre-release。
- Release Candidate。
- 页面明确列出的其他开发版本。

通过 MediaWiki API 或可靠页面解析获取数据。

不得只硬编码几个格式编号。

不得推测未公布的未来版本。

## 7.2 数据库

至少建立：

```text
minecraft_pack_formats
minecraft_pack_format_versions
minecraft_pack_format_sync_logs
minecraft_pack_format_history
```

支持：

- 整数格式。
- 小数格式。
- Major / Minor。
- 一对多版本映射。
- 正式版和 Snapshot 区分。
- 版本范围。
- 新版 `min_format` / `max_format`。
- `supported_formats`。

保留原始数据和来源。

## 7.3 自动同步

支持：

- 初次安装完整初始化。
- 每日自动同步。
- 管理员手动同步。
- 差异对比。
- 新增和更新。
- 历史记录。
- JSON 导入。
- CSV 导入。
- 手动修正。
- 数据回滚。

同步失败必须保留上一份有效数据。

虚拟主机无 Cron 时仍然支持手动同步。

不得在每次访问页面时请求 Wiki。

## 7.4 检测到的游戏版本展示方式

原先的“检测到的游戏版本”展示方式必须修改。

统一改成：

**建议使用的版本：xxx**

其中 `xxx` 必须是具体的 Minecraft Java Edition 版本号。

例如：

```text
建议使用的版本：1.21.10
```

不要只显示：

```text
检测到的游戏版本：1.21.x
```

也不要只显示一个无法执行判断的版本范围。

### 推荐版本选择逻辑

1. 根据资源包的格式数据查询所有对应 Minecraft Java Edition 版本。
2. 优先选择正式发布版本。
3. 在符合条件的正式版中，优先推荐最新的稳定正式版本。
4. 如果没有对应正式版，才选择 Pre-release 或 Release Candidate。
5. 如果仍没有，再选择 Snapshot。
6. 如果没有可靠映射，显示“暂无法确定建议版本”，不得猜测。
7. 显示版本类型，Snapshot 等非正式版必须明确标识。
8. 如果资源包使用了 `min_format`、`max_format` 或 `supported_formats`，根据其范围执行兼容性判断，不能只检查单个整数。
9. 当存在多个候选版本时，可以显示一个主推荐版本及其他兼容版本列表。

展示示例：

```text
建议使用的版本：1.21.10

版本类型：正式版
Resource Pack Format：69.0
```

若只有 Snapshot 可匹配：

```text
建议使用的版本：25wXXa

版本类型：Snapshot（非正式版）
```

实际版本号必须来自同步数据，以上仅是展示示例。

必须明确提示：格式匹配不代表资源包内全部纹理、模型、声音等内容完全兼容。

## 7.5 Pack Format 查询页面与 Sitemap

提供：

```text
/minecraft/pack-formats
```

支持搜索和筛选。

必须遵循以下 Sitemap 规则：

- Pack Format 详情页不得被收录到 sitemap.xml。
- 不得将每一个 Minecraft 版本的详情 URL 批量写入 Sitemap。
- 动态生成 Sitemap 时必须显式排除 Pack Format 详情路由。
- Sitemap 生成器必须有自动化测试。
- 不能仅通过前端隐藏链接实现排除。
- 如果未来增加详情页路由，默认也不进入 Sitemap，除非管理员明确配置。

普通查询入口是否进入 Sitemap 可以单独配置。

# 八、数据库索引命名规范与 MySQL 5.7 兼容性

这是强制要求，不能遗漏。

MySQL 标识符最大长度为 64 个字符。

Laravel 自动生成的索引名可能超过 MySQL 上限。

已知问题：

```text
minecraft_pack_format_versions_minecraft_pack_format_id_version_type_index
```

长度达到 74 个字符，会超过 MySQL 64 字符限制。

因此必须对 Migration 中的索引显式指定短名称。

## 8.1 必须使用的索引名称

针对：

`minecraft_pack_format_versions`

指定：

```php
$table->index(
    ['minecraft_pack_format_id', 'version_type'],
    'mcpf_versions_format_type_index'
);
```

索引名：

```text
mcpf_versions_format_type_index
```

不得再由 Laravel 自动生成长名称。

## 8.2 全项目索引审查

必须检查所有：

- 普通索引。
- 唯一索引。
- 复合索引。
- 外键约束名称。
- 其他数据库约束名称。

所有索引名称和显式约束名称必须小于或等于 64 个字符。

建议统一使用短前缀：

```text
users_email_unique
rp_user_status_index
rp_token_unique
mcpf_format_index
mcpf_versions_format_type_index
dl_logs_pack_date_index
```

以上名称仅为建议命名，实际命名必须保证唯一且不超过限制。

对外键也应显式命名，避免 Laravel 自动生成超长名称。

删除索引时也必须使用显式短名称。

## 8.3 自动化检查

在 CI 和 Migration 测试中加入索引命名检查：

- 统计每个索引名称长度。
- 统计外键名称长度。
- 超过 64 字符直接使测试失败。
- 检查索引重名。
- 检查迁移能否在 MySQL 5.7 上正常执行。

不得只修复一个已知索引，而忽略其他潜在长名称。

# 九、SHA-1 与匿名下载

上传完成后对最终存储文件计算：

```php
$sha1 = hash_file('sha1', $path);
```

要求：

- 40 位小写十六进制。
- 计算最终保存文件的原始字节。
- 下载字节必须与 SHA-1 对应。
- 存储迁移后重新校验。

下载链接：

```text
https://respack.example.com/dl/{random_token}
```

要求：

- 匿名访问。
- 无需登录。
- 无需 Cookie。
- 无需 Authorization Header。
- 高熵 Token。
- 数据库只保存 Token 摘要。
- 用户可停用和重置 Token。
- 删除资源包后立即失效。

下载支持：

- GET
- HEAD
- Range
- 断点续传
- Content-Length
- Content-Type
- Content-Disposition
- ETag
- Last-Modified
- 206
- 416

HEAD 不计完整下载次数。

Range 不应重复增加完整下载次数。

本地存储优先使用 Nginx X-Accel-Redirect；Apache 和虚拟主机使用 PHP 流式下载。

S3 和 WebDAV 使用经过安全处理的远程读取或流式下载。

所有下载都必须验证资源包状态及过期时间。

游客资源包过期后必须立即禁止下载，即使物理文件尚未被清理。
