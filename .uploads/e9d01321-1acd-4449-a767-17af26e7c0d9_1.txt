# Next Respack — 完整项目开发与交付任务书

## 1. 项目目标

你是一支完整的软件工程团队，由架构师、PHP 后端工程师、前端工程师、数据库工程师、安全工程师和测试工程师组成。

请从零开始设计并实现 **Next Respack**：一个面向 Minecraft Java Edition 服务器管理员的资源包上传、管理、校验、托管和下载链接生成平台。

项目不是通用网盘，不需要支持任意文件。核心功能是：

1. 用户注册、登录和账户管理。
2. 上传 Minecraft Java Edition 资源包 ZIP。
3. 自动校验 ZIP 完整性及 Minecraft 资源包结构。
4. 自动生成安全的内部文件名。
5. 自动计算 SHA-1。
6. 自动识别 Minecraft Resource Pack Format 和对应游戏版本。
7. 为每个资源包生成独立、匿名、长期有效的 HTTPS 下载链接。
8. 自动生成 Minecraft 服务端 `server.properties` 配置。
9. 用户可以管理、停用、删除自己的资源包。
10. 管理员可以管理用户、存储、系统配置及 Pack Format 数据。
11. 首次访问时提供完整的网页安装向导。
12. 同时支持虚拟主机和独立 VPS 部署。

最终交付必须是一个可以实际安装、运行、测试和维护的完整工程，不接受只有界面、静态页面、伪代码或未实现功能的演示项目。

# 2. 技术栈与运行环境

## 2.1 核心技术栈

- PHP：8.3+
- Web 框架：Laravel 13
- 数据库：MySQL 8.0（首选）
- 前端：Blade + Tailwind CSS + Alpine.js
- 构建工具：Vite
- 数据库迁移：Laravel Migrations
- 身份认证：Laravel 原生认证机制或经过审查的成熟组件
- 文件存储：Laravel Filesystem 抽象
- API：按实际需求提供 REST API
- 测试：Pest 或 PHPUnit

所有依赖必须固定兼容版本，并提供 `composer.lock`。

不得为了方便开发而使用不兼容 PHP 8.3 的依赖。

## 2.2 必须支持的部署环境

### A. 虚拟主机

目标环境：

- PHP 8.3
- MySQL 8.0
- Apache 或 Nginx
- HTTPS
- 通过 FTP/SFTP 上传项目文件
- 不保证 SSH 权限
- 不保证 Composer 命令行
- 不保证 Node.js
- 不保证 Cron
- 不保证用户拥有 Web 根目录以外的任意目录权限

必须做到：

- 提供完整依赖的生产发行包，包含 Composer `vendor`。
- 提供已经构建好的前端静态资源。
- 用户可以通过浏览器完成安装。
- 不要求用户在服务器上运行 `composer install`。
- 不要求用户运行 `npm install` 或 `npm run build`。
- 不要求用户使用 SSH 执行数据库迁移。
- 不要求用户拥有 Root 权限。
- 不依赖必须常驻运行的 Queue Worker。
- 不依赖 Redis、Supervisor 或 Docker。
- 没有 Cron 时，核心上传、下载、管理功能仍然正常。
- 定时任务应有手动执行和替代方案。

如果虚拟主机不能修改网站 Document Root，必须提供安全的兼容部署方案。

推荐结构：

```text
/home/account/
├── next-respack/
│   ├── app/
│   ├── bootstrap/
│   ├── config/
│   ├── database/
│   ├── resources/
│   ├── routes/
│   ├── storage/
│   ├── vendor/
│   ├── .env
│   └── artisan
│
└── public_html/
    ├── index.php
    ├── .htaccess
    └── assets/
```

其中：

- Laravel 项目主体放在非公开目录。
- `public_html` 只放公开入口和静态资源。
- `index.php` 必须正确引用项目主体目录。
- 禁止公开访问 `.env`、`vendor`、`storage`、`database`、日志和备份。
- 不得为了兼容虚拟主机而将整个 Laravel 项目暴露在网站根目录。

如果主机允许独立设置 Document Root，优先直接指向 Laravel 的 `public/`。

### B. VPS

支持：

- Debian / Ubuntu / Azure Linux 等 Linux 发行版。
- PHP 8.3+
- MySQL 8.0
- Nginx 或 Apache
- PHP-FPM
- Composer
- Node.js（仅开发或构建阶段需要）
- Cron
- Laravel Scheduler
- 可选 Redis
- 可选 Supervisor
- 可选 Docker

VPS 可以启用额外性能优化，但不能让这些组件成为核心功能运行的必要条件。

- OpenSSL

如果缺少必需扩展，显示具体扩展名称、当前状态和解决方法，不允许继续进入正式安装。

# 3. 首次访问网页安装向导

这是项目的核心交付功能之一。

首次访问 Next Respack 时，如果尚未安装，自动进入：

`https://example.com/install`

安装完成后，普通用户访问网站首页。

安装界面应采用现代化的分步向导，支持上一步、下一步、返回修改和安装失败重试。

## 3.1 安装向导步骤

### Step 0：欢迎界面

显示：

- Next Respack Logo
- 产品名称和版本号
- 项目简介
- 当前安装状态
- 系统要求
- 开始安装按钮

提供简体中文和英文界面，默认简体中文。

### Step 1：环境检测

自动检测：

- PHP 版本。
- PHP 必需扩展。
- PHP 配置。
- MySQL 驱动。
- 文件上传功能。
- 文件系统读写权限。
- `storage/` 写入权限。
- `bootstrap/cache/` 写入权限。
- 前端静态资源是否存在。
- HTTPS 状态。
- 安装目录安全性。

显示：

- <通过>：符合要求。
- <警告>：可以继续，但存在限制。
- <失败>：必须解决才能继续。

提供对应修复说明。

### Step 2：数据库选择与连接配置

安装器提供数据库类型选择界面。

支持的驱动：

1. MySQL 8.0：正式推荐。
2. MariaDB：仅在目标版本通过兼容性测试后启用。
3. SQLite：可选轻量部署模式，必须提示适用场景及并发限制。

MySQL 配置字段：

- 数据库主机 Host
- 端口 Port，默认 3306
- 数据库名称 Database
- 用户名 Username
- 密码 Password
- 字符集，默认 utf8mb4
- 排序规则，默认 utf8mb4_unicode_ci

提供：

- 测试数据库连接。
- 验证数据库是否存在。
- 验证数据库账号是否拥有必要权限。
- 验证数据库版本。
- 显示错误信息。
- 连接成功后允许继续。

特别要求：

虚拟主机环境中，数据库通常已经由服务商创建。安装器不得默认拥有 CREATE DATABASE 权限。

允许用户直接使用已创建的数据库和数据库账号。

数据库迁移只能在选定数据库中创建应用所需的数据表，不得删除或覆盖无关数据表。

### Step 3：存储后端选择

提供存储驱动选择界面。

#### 方案 A：本地存储（默认推荐）

- 文件保存在服务器本地。
- 支持虚拟主机。
- 支持 VPS。
- 不依赖外部存储服务。

配置：

- 存储目录。
- 目录写入检测。
- 可用空间检测。
- 存储路径安全检测。

默认路径：

```text
storage/app/private/resource-packs/
```

不得将私有 ZIP 直接存放在公开 Web 根目录。

#### 方案 B：S3 兼容对象存储（可选）

预留支持：

- Amazon S3
- Cloudflare R2
- 其他 S3-compatible 服务

配置：

- Endpoint
- Region
- Bucket
- Access Key
- Secret Key
- Path Style
- 自定义公开域名（可选）

必须测试连接、读写和删除权限。

对象存储凭据不得返回给普通用户，也不得暴露在前端。

若对象存储不可用，不影响本地存储功能。

#### 存储架构要求

使用统一的 Storage Adapter 接口。

例如：

```text
StorageInterface
├── LocalStorageAdapter
└── S3StorageAdapter
```

业务逻辑不得直接依赖某一个具体存储驱动。

资源包下载必须通过 Next Respack 的下载控制器或经过授权的安全下载机制，不得默认公开对象存储桶。

### Step 4：站点基础配置

配置：

- 网站名称，默认 Next Respack。
- 网站 URL。
- 网站域名。
- 默认语言。
- 时区。
- 网站描述。
- 默认最大上传大小。
- 用户默认存储配额。
- 是否允许公开注册。
- 是否启用邮箱验证。
- 管理员通知邮箱。

必须正确处理 HTTPS 和反向代理环境。

### Step 5：创建第一个管理员账户

第一个管理员必须在安装过程中创建。

字段：

- 用户名
- 邮箱
- 密码
- 确认密码

要求：

- 用户名唯一。
- 邮箱唯一。
- 密码符合安全策略。
- 密码使用 Argon2id 或安全的 Laravel 密码哈希机制。
- 第一个账户直接授予超级管理员角色。

- 不允许安装完成后自动创建公开默认管理员账户。

显示所有配置摘要：

- 数据库类型。

### Step 7：执行安装

自动完成：

1. 生成安全的 APP_KEY。
2. 保存环境配置。
3. 初始化数据库。

提供：

- 进入后台。
- 查看安装信息。
- 查看部署说明。

## 3.2 安装器安全要求

必须实现：

- 安装状态检测。
- 一次性安装锁。
- 安装步骤 Session 保护。
- CSRF 防护。
- 数据库连接测试。
- 防止重复初始化。
- 防止并发安装。
- 安装失败时保留可恢复状态。
- 不在页面输出数据库密码或 APP_KEY。
- 防止任意路径写入。
- 防止通过修改 URL 绕过安装步骤。
- 防止普通用户重新进入安装流程。

安装完成后：

- 创建安装锁文件。
- 数据库中记录安装状态。
- 安装路由自动禁用。
- 即使删除安装锁文件，也不能仅凭文件缺失重新安装。
- 不提供公开的重装接口。
- 如需重装，必须由服务器管理员手动执行受保护的维护操作。

如果安装器无法写入 `.env`，必须明确提示权限问题，不得静默将敏感凭据保存在公开目录。

安装器不能依赖 Composer 在网页运行时下载依赖。所有依赖必须在开发或构建阶段准备好。

# 5. Minecraft 资源包上传与校验

## 5.1 上传要求

只允许 Minecraft Java Edition 资源包 ZIP。

禁止：

- RAR
- 7z
- EXE
- APK
- 任意其他文件类型

默认限制：

- 单个文件最大 512 MB。
- 用户默认总存储配额 2 GB。

管理员可以修改限制。

必须同时考虑 PHP、Web Server 和应用层的上传限制。

## 5.2 ZIP 安全检查

上传时执行：

1. 扩展名检查。
2. MIME 检查。
3. ZIP 文件签名检查。
4. ZIP 完整性检查。
5. CRC 检查。
6. 文件数量限制。
7. 解压后大小限制。
8. 压缩比限制。
9. ZIP Bomb 检测。
10. 路径穿越检测。
11. 符号链接检测。
12. 非法文件名检测。

禁止将 ZIP 解压到公开目录。

校验时只读取必要文件，不允许直接信任 ZIP 内部路径。

## 5.3 Minecraft 资源包结构校验

必须检查 ZIP 根目录中的：

```text
pack.mcmeta
```

可选：

```text
pack.png
```

检查：

- 是否存在 `pack.mcmeta`。
- JSON 是否有效。
- 是否存在合法的 `pack` 对象。
- 是否包含可识别的格式字段。
- `pack_format` 是否有效。
- `supported_formats` 是否有效。
- `min_format` 是否有效。
- `max_format` 是否有效。
- 字段类型是否符合 Minecraft 对应版本的规范。

不得将其他目录内的 `pack.mcmeta` 错误识别为根目录文件。

校验结果分类：

- ZIP_INVALID
- PACK_INVALID
- METADATA_INVALID
- FORMAT_UNKNOWN
- VALID
- VALID_WITH_WARNING

保留原始 `pack.mcmeta` 内容，便于后续兼容新的格式。

# 6. Minecraft Resource Pack Format 数据库与自动同步

这是项目的独立核心模块。

数据源：

https://minecraft.wiki/w/Pack_format

目标是完整采集 Minecraft Java Edition 的 Resource Pack Format 历史映射。

注意：这里指的是 Resource Pack Format，不是 Data Pack Format，也不是 Bedrock Edition 格式。

## 6.1 数据采集

必须采集页面中的完整可识别数据：

- Java Edition 正式版。
- Pre-release。
- Release Candidate。
- Snapshot。
- 其他页面明确标注的开发版本。

不得只硬编码几个示例。

优先使用 MediaWiki API 获取页面内容和结构化信息。

如果需要解析 HTML，必须考虑页面结构变化。

同步时保存：

- 原始页面数据。
- 来源 URL。
- 获取时间。
- 解析器版本。
- 数据集版本。
- 数据变更记录。

未在数据源中公布的未来版本不得推测。

## 6.2 格式数据结构

必须支持：

- 整数格式。
- 小数格式。
- Major / Minor。
- 多个 Minecraft 版本对应同一格式。
- 同一 Minecraft 版本的正式版与 Snapshot 区分。
- 格式范围。
- 新版本的 min_format / max_format。

例如：

```json
{
  "edition": "java_resource_pack",
  "format_major": 69,
  "format_minor": 0,
  "format_value": "69.0",
  "minecraft_versions": [
    "1.21.9",
    "1.21.10"
  ],
  "version_type": "release"
}
```

上述仅作为数据结构示例，实际版本和格式必须以数据源为准。

不能将 `69.1` 错误转换为 `691` 或 `69`。

必须区分 JSON 数字、字符串和数组。

## 6.3 数据库表

至少建立：

`minecraft_pack_formats`

字段建议：

- id
- edition
- format_major
- format_minor
- format_value
- version_name
- version_type
- version_channel
- is_snapshot
- is_prerelease
- is_release_candidate
- release_date
- source_url
- source_updated_at
- created_at
- updated_at

`minecraft_pack_format_versions`

用于支持一对多版本映射。

`minecraft_pack_format_sync_logs`

记录同步时间、状态、错误和数据变更。

`minecraft_pack_format_history`

保留每次数据变更的历史版本。

## 6.4 自动同步机制

支持：

- 首次安装完整初始化。
- 每日自动同步。
- 管理员手动同步。
- 数据差异比较。
- 新数据插入。
- 已有数据更新。
- 数据变更记录。
- 同步失败保护。
- 管理员手动修正。
- JSON / CSV 导入。
- 历史数据回滚。

虚拟主机没有 Cron 时：

- 仍然支持管理员手动同步。
- 可以使用限频的请求触发调度机制。
- 不允许每次用户访问页面都请求 Minecraft Wiki。
- 不允许依赖常驻后台进程。

VPS 可以使用 Laravel Scheduler 和 Cron。

同步失败时必须保留上一份有效数据，不得清空数据库或覆盖有效记录。

只有经过完整性校验的数据才允许正式发布。

## 6.5 上传时自动识别格式

解析资源包 `pack.mcmeta`。

根据格式数据库判断：

- Resource Pack Format。
- 对应 Minecraft Java Edition 版本。
- 正式版或 Snapshot。
- 支持的版本范围。
- 是否为未知格式。
- 是否存在格式兼容警告。

上传详情展示识别结果。

特别要求：

格式匹配不代表资源包中的纹理、模型、声音和其他资源一定兼容对应 Minecraft 版本。

不得向用户保证格式匹配即代表资源包完全兼容。

## 6.6 Pack Format 查询页面

提供：

`/minecraft/pack-formats`

功能：

- 按 Minecraft 版本搜索。
- 按 Resource Pack Format 搜索。
- 按正式版筛选。
- 按 Snapshot 筛选。
- 按 Pre-release 筛选。
- 按 Release Candidate 筛选。
- 查看格式历史。
- 查看数据更新时间。
- 查看数据来源。

管理员后台提供：

- 手动同步。
- 同步日志。
- 数据差异。
- 手动修正。
- JSON 导入。
- CSV 导入。
- 历史版本恢复。

# 7. 文件命名、SHA-1 与下载系统

## 7.1 文件命名

上传后不使用用户提供的原始文件名作为实际存储文件名。

使用 UUIDv7 或密码学安全随机 ID。

例如：

```text
resource-packs/
├── 019a9f12-xxxx.zip
├── 019a9f13-xxxx.zip
└── 019a9f14-xxxx.zip
```

原始文件名保存在数据库。

## 7.2 SHA-1

使用最终保存文件的原始字节计算：

```php
$sha1 = hash_file('sha1', $path);
```

要求：

- 结果为 40 位小写十六进制字符串。
- 对最终存储的 ZIP 计算。
- 不得对解压内容计算。
- 不得使用上传前的临时数据冒充最终文件校验值。
- 上传完成后验证文件大小和 SHA-1。
- 下载文件内容必须与记录的 SHA-1 对应。

SHA-1 仅用于 Minecraft 资源包完整性校验，不得作为用户认证或安全签名机制。

## 7.3 匿名下载链接

格式：

```text
https://respack.example.com/dl/{random_token}
```

要求：

- 无需玩家注册。
- 无需登录。
- 无需 Cookie。
- 无需 Authorization Header。
- 支持 Minecraft 服务端直接访问。
- 使用高熵随机 Token。
- 数据库只保存 Token 摘要。
- Token 不得使用连续自增 ID。
- 用户可以停用链接。
- 用户可以重置 Token。
- 删除资源包后链接立即失效。
- 默认长期有效。

## 7.4 HTTP 下载协议

支持：

- GET
- HEAD
- Range
- 断点续传
- Content-Length
- Content-Type
- Content-Disposition
- ETag
- Last-Modified

要求正确处理：

- 206 Partial Content
- 416 Range Not Satisfiable
- 404 Not Found
- 403 Forbidden

HEAD 请求不增加下载次数。

Range 请求不得被错误地重复计为多个完整下载。

生产环境优先支持 Nginx `X-Accel-Redirect`。

开发环境和虚拟主机环境提供 PHP 安全流式下载模式。

不得通过公开目录直接暴露私有资源包。

## 7.5 下载统计

记录：

- 资源包 ID。
- 下载时间。
- 下载状态。
- 请求方法。
- 文件大小。
- Range 请求情况。

可选记录匿名化 IP 信息。

不得在普通日志中记录下载 Token 原文。

支持下载次数统计。
